# Olist 数据清洗规则

## 1. 总体原则

1. `data/raw/` 只保存原始文件，禁止覆盖、重命名字段或手工修改。
2. 清洗结果写入 `data/processed/`，分析汇总表写入独立的数据集或数据库。
3. 每条清洗规则必须能解释原因，并能在 Notebook 或脚本中重复执行。
4. 清洗不等于删除：业务异常订单保留，使用状态字段和分析筛选字段区分。

## 2. 类型与格式统一

| 数据对象 | 清洗规则 |
|---|---|
| ID 字段 | 全部按字符串读取，禁止转换为数字或截断前导零。 |
| 邮编前缀 | 按 5 位文本保存；客户和卖家邮编分别保留原字段。 |
| 时间字段 | 统一解析为 datetime；解析失败记为缺失并记录质量问题，不擅自填日期。 |
| 金额字段 | 转换为数值，保留原始精度；`price`、`freight_value`、`payment_value` 分开保存。 |
| 州与城市 | 州统一大写，城市去除首尾空格；不在原始层翻译城市名称。 |
| 品类名称 | 保留葡语原名，同时通过翻译表生成英文展示名。 |

## 3. 重复记录处理

| 表 | 判定与处理 |
|---|---|
| orders | `order_id` 应唯一；完整重复行检查后保留一行，异常记录写入质量报告。 |
| customers | `customer_id` 应唯一；`customer_unique_id` 可以对应多个订单收货身份，不去重。 |
| order_items | 使用 `order_id + order_item_id` 作为明细键；不按商品或金额去重。 |
| payments | 使用 `order_id + payment_sequential` 定位支付记录；一订单多笔支付必须保留。 |
| reviews | `review_id` 可能重复，不能仅凭它删除记录；以 `order_id` 聚合评价指标。 |
| geolocation | 先删除完全重复行，再按邮编前缀聚合经纬度和地区；禁止直接关联原始地理表。 |
| products / sellers / translation | 各自主键或品类键应唯一，重复记录进入质量检查。 |

## 4. 缺失值处理

### 4.1 订单和物流

- `order_approved_at`、交承运商时间、客户签收时间缺失时不做人工填补。
- 只有所需时间均存在时，才计算审批耗时、发货时长和配送时长。
- 没有签收时间的订单不能用于已完成订单的配送时效和延迟率。
- 缺失时间仍保留在订单状态分析中，用于观察未完成订单结构。

### 4.2 商品

- `product_category_name` 缺失统一标记为 `uncategorized`。
- 有葡语品类但无英文翻译时保留葡语名称，并标记为 `untranslated`。
- 商品重量和尺寸缺失不在描述性分析中强制填补；若建模需要填补，必须单独记录方法。

### 4.3 评价

- 缺失评价标题或正文不等于差评，生成 `has_review_comment` 标记即可。
- `review_score` 缺失的记录不能计入平均评分和差评率分母。

## 5. 业务筛选口径

| 分析用途 | 默认筛选 |
|---|---|
| 订单状态分布 | 保留全部 `order_status` |
| 完成订单经营大盘 | `order_status = 'delivered'` |
| GMV、客单价、品类销售 | 完成订单；金额来自 `order_items.price` |
| 运费分析 | 完成订单；单独使用 `freight_value` |
| 用户复购与 RFM | 完成订单；用户键使用 `customer_unique_id` |
| 物流时效 | 完成订单且相关时间字段完整 |
| 延迟率 | 完成订单且签收时间、预计送达时间完整 |
| 满意度 | 有 `review_score` 的订单；一单多评价先聚合 |

## 6. 金额口径

- 商品 GMV：`SUM(price)`，不含运费。
- 运费金额：`SUM(freight_value)`，单独报告。
- 含运费交易额：`SUM(price + freight_value)`。
- 实付金额：`payment_value` 先按 `order_id` 汇总，再与订单级表关联；不直接作为商品 GMV。
- 缺少商品明细的订单不计入商品 GMV，但保留在订单状态和支付分析中。

## 7. 时间口径

- 默认趋势时间使用 `order_purchase_timestamp`，按月生成 `order_month`。
- 2018-09 至 2018-10 是数据末端的截尾月份；完整月度趋势默认分析至 2018-08，并在报告中注明。
- 配送时长 = `order_delivered_customer_date - order_approved_at`。
- 延迟订单 = 实际签收时间晚于预计送达时间。

## 8. 清洗质量检查

每次生成处理数据时必须检查：

- 行数是否在预期范围内；
- 主键是否重复；
- 外键关联是否出现孤立记录；
- 金额是否出现负数或异常极值；
- 时间顺序是否合理（审批不早于下单、签收不早于发货）；
- 连接前后订单数和金额是否发生非预期膨胀；
- 清洗日志是否记录处理时间、输入文件和规则版本。
