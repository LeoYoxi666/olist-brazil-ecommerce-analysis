# Olist 项目简历与面试介绍

以下内容用于准确、简洁地介绍本项目。文中商业金额表示历史分析范围，不代表已实现的
因果增量或会计利润。

## 1. 中文简历要点

- 基于 9 张 Olist 巴西电商原始数据表，使用 Python、pandas 与 SQLite 搭建可复现的
  端到端分析流程，产出 13 张清洗/主题数据表、12 项数据质量检查、11 张业务分析表
  及独立 HTML 运营仪表盘。
- 围绕 96,478 个已交付订单和 R$13.22M 商品 GMV，完成用户 RFM、月度留存、品类、
  卖家、地区、配送和评价分析，识别 41 个合格 cohort-RFM 客群及 1,886 条卖家—州
  配送风险行动队列。
- 修正并测试 RFM 并列值和一次购买用户误分类问题，引入样本量门槛、影响优先级、
  留出组实验建议和商业解释边界；通过 pytest、Black、isort、Flake8、mypy 与
  GitHub Actions CI 保证可维护性。

## 2. 30 秒面试介绍

这个项目的目标不是只做几张图，而是把 9 张相互关联的电商原始表变成一个可复现、
可解释、可持续迭代的运营分析项目。我先建立清洗、关联、质量检查和 SQLite 数据层，
再围绕已交付订单分析用户留存、RFM、品类、卖家和配送表现。过程中我发现传统分位数
RFM 会把相同的一次购买用户随机分到不同等级，因此改成并列值稳定的评分规则并增加
测试。最终项目给出了 41 个留存目标客群和 1,886 条配送行动队列，并通过在线仪表盘、
方法文档和 CI 保证结果可展示、可复现、可维护。

## 3. 面试展示顺序

1. 打开在线仪表盘，解释三个管理决策优先领域。
2. 打开数据字典和方法文档，说明指标口径与质量控制。
3. 解释并列值稳定的 RFM 修正及其自动化测试。
4. 展示 cohort-RFM 目标客群和卖家—州行动队列，说明如何从分析转为运营决策。
5. 展示 GitHub Actions 运行记录，证明项目具备可复现性和工程质量。

## 4. 解释边界

不要把分析范围内的 GMV 描述成已追回收入、预测增量、利润或营销 ROI。该数据集支持
运营优先级和实验设计，但不包含营销曝光、广告支出、商品成本、平台佣金或浏览事件。
